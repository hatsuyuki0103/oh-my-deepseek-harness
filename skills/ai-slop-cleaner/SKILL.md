# AI Slop Cleaner（反冗余清理）

## 何时使用

- 代码能跑但臃肿、噪音大、重复、过度抽象；
- 用户说 "cleanup" / "refactor" / "deslop"；
- 后续实现留下了重复代码、死代码、弱边界、缺失测试、兜底残留、多余包装层；
- 需要纪律化清理，而不是大重写。

## 范围与纪律

- 可接受**文件列表范围**（如 ralph 会话改过的文件），清理严格限定在内；
- ralph 工作流的强制 deslop 遍只清 ralph 自己改的文件；
- **先锁行为再动刀**；每遍一次只清一种气味；不在同一编辑集里混无关重构。

## 流程

1. **先用回归测试锁行为**
   - 明确什么行为不许变；
   - 清理候选开刀前，先补/跑定向回归测试；
   - 行为尚未被测试覆盖时，先建最窄的必要覆盖；
   - 兜底类代码：主路径与保留的兼容/失效安全兜底都要有测试。
2. **先写清理计划再动代码**
   - 列出要清的具体气味；限定范围；从最安全/最高信号到最危险的顺序排；计划不显式不动手。
3. **编辑前盘点兜底类代码**
   - 在范围内搜兜底信号：quick hack、临时 workaround、fallback if it fails、吞错、静默默认、宽兼容垫片、重复的替代执行路径；
   - 逐个分类再决定动或不动：
     - **掩蔽型兜底 slop**：隐藏错误/证据、绕过主契约、压制测试/校验、吞失败、静默默认、无测试的替代路径 → 优先根因修复/删除/边界修复/显式失败行为；
     - **有依据的兼容/失效安全兜底**：限定在外部/版本/失效安全边界内、有理由文档、保留失败证据、主路径与兜底都有回归测试 → 保留；
   - 宽泛/跨层/架构性的兜底类代码：交给 ralplan 共识决议，不擅自改。
4. **动刀前分类**：兜底残留 / 重复 / 死代码（无用代码、不可达分支、陈旧开关、调试残留）/ 过度抽象（透传包装、投机间接层、单次使用的辅助层）/ 边界违规（隐藏耦合、泄漏职责、错层导入或副作用）/ 缺失测试。
   - 视觉/UI 类气味（配色、阴影、网格密度等）在 DSH 无视觉环境下不做像素判断：涉及视觉取舍时保留现状并在报告中注明「需用户视觉确认」。
5. **逐气味执行（每遍后重跑验证）**：
   - 兜底解析闸（先过）→ Pass 1 死代码删除 → Pass 2 去重 → Pass 3 命名/错误处理 → Pass 4 测试补强。
6. **质量闸**：回归测试保持绿；lint/类型检查过；相关单测过；可用时静态/安全扫描过；diff 最小且限定范围；无新抽象/新依赖。
7. **证据密集报告**：改动文件、简化内容、兜底发现与分类、跑过的检查、剩余风险、有意推迟的清理。

## 输出格式

```
AI SLOP CLEANUP REPORT
======================

Scope: <文件或区域>
Behavior Lock: <锁行为的回归测试>
Cleanup Plan: <有界气味清单与顺序>
Fallback Findings: <none 或 发现 -> 掩蔽型/有依据兜底 -> 处置>

Passes Completed:
- 兜底解析闸 - <根因修复 / 显式失败 / 保留有依据兜底 / 交 ralplan>
1. 死代码删除 - <简述>
2. 去重 - <简述>
3. 命名/错误处理 - <简述>
4. 测试补强 - <简述>

Quality Gates:
- 回归测试: PASS/FAIL | Lint: PASS/FAIL | 类型检查: PASS/FAIL | 单测: PASS/FAIL

Changed Files / Remaining Risks: ...
```

## 最终清单

- [ ] 动刀前行为已被测试锁定
- [ ] 清理计划先于代码
- [ ] 兜底类代码已盘点分类
- [ ] 每遍一种气味、每遍后验证
- [ ] 质量闸全绿、diff 最小
- [ ] 报告含兜底分类与剩余风险
