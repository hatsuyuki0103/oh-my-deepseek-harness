# Build Fix（构建修复）

## 定位

处理编译/打包/类型检查失败。纪律与 analyze/executor 一致：先复现、再定位、最小修、后全验。DSH 常见构建面：

- 后端：mvn -pl ruoyi-admin -am -DskipTests compile（或 clean verify）；常见失败：依赖版本冲突、缺失 .m2 元数据、Java 版本不匹配、Lombok/注解处理；
- 前端：yarn build:prod / vite build；常见失败：类型错误、未定义导入、模板编译错误；
- 工具：node --test 语法错误、pnpm 安装脚本失败。

## 步骤

1. **复现**：跑用户给的（或项目标准）构建命令，保存完整输出与退出码；后台任务跑长构建；
2. **读错误**：从第一个错误开始，不跳着修；区分「根因错误」与「级联错误」（后者是前者引发的连锁反应，修根因后自动消失）；
3. **定位**：grep/read 相关文件；对照最近 git diff 判断是否回归；环境类错误（JDK/Node 版本、依赖缓存）先验证环境事实；
4. **最小修复**：只改让构建恢复所需的最小集；不顺手重构；不引入新依赖；改动与既有模式一致；
5. **全量复验**：修复后重跑同一构建命令，读输出确认 exit 0；涉及多模块时跑完整构建面；相关单测一并跑；
6. **报告**：根因、修复、验证证据；若失败是环境限制（如断网拉依赖），如实报告而非"修好了"。

## 输出契约

```
## Build Fix Report

Command: <构建命令>
Root cause: <根因 + file:line>

Changes:
- <文件> — <最小修复>

Verification:
- <命令> → exit 0 / 输出摘录
- 相关测试 → <结果>

Remaining risks:
- <已知残余/未验证面>
```

## 最终清单

- [ ] 失败真实复现过（有原始输出）
- [ ] 根因与级联错误已区分
- [ ] 改动最小且未引入新依赖
- [ ] 同一构建命令复验 exit 0
- [ ] 环境类失败已如实报告
