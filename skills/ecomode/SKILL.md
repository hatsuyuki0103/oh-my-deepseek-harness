# Ecomode（省 token 模式）

## 定位

Ecomode 是一个**修饰符**，叠加在执行工作流上（ralph / ultrawork / autopilot / 普通开发），让每一分 token 花在刀刃上。DSH 没有多模型档位切换，省钱靠**决策纪律**而非模型选择。

## 省 token 纪律（按收益排序）

1. **能自做不委派**：单文件小改、直接读改验证的工作，主会话直接做；subagent 只在「独立、有界、并行可提效」时用；
2. **能少不不少**：合并同类子任务到一个 subagent（一次对话处理多个小件），而不是每个小件开一个；
3. **能轻不重**：简单查询/证据收集用简短 prompt（一句话目标 + 输出格式）；不要每次都塞整个角色文件 + 长篇上下文；
4. **并行只在独立时**：有依赖或共享文件的"并行"会造成返工，比串行更贵；
5. **后台任务收口**：长命令（构建/测试）run_in_background，用 job_output 读结果——不要让结果塞满主上下文；
6. **读输出要裁剪**：只读与结论相关的尾部/关键行，不全量吞日志；
7. **控制文档体积**：给 subagent 的上下文只给必要切片 + 引用路径，不粘贴整文件；
8. **减少重复轮次**：一次把验收标准、输出格式、停止条件写清楚，避免来回澄清。

## 委派决策表

| 工作 | 方式 |
|------|------|
| 单文件小改/紧迭代 | 主会话自做 |
| 独立多文件批量改 | 合并成一个 executor subagent |
| 简单查找/证据 | 主会话 grep/glob，或一个短 prompt subagent |
| 复杂分析/审查 | 才动用完整角色提示词（architect/critic 等） |
| 文档/研究 | web_search 直接查，或一个 researcher 型 subagent |

## 与工作流组合

- `eco ralph`：持久闭环但每轮委派最小化、验证命令聚合；
- `eco ultrawork`：并行通道数控制在必要量，每路验收标准先写清；
- `eco autopilot`：各阶段产物精简，评审子代理 prompt 只给 diff + 上下文快照路径。

## 输出契约

收尾时报告：委派次数、并行通道数、省掉的重复动作、以及「哪些 token 开销本可避免」。

## 最终清单

- [ ] 委派决策表被遵守（自做/合并/短 prompt）
- [ ] 并行仅用于独立工作
- [ ] 长命令后台化且输出被裁剪
- [ ] 子代理上下文只含必要切片
- [ ] 未以牺牲验证质量为代价省 token（证据要求不缩水）
