# 写作技法与外部技能吸收对照

> 本手册回答两个问题：① 外部同类小说 Agent 技能里，哪些做法值得吸收、哪些刻意不复刻；② 真正落笔时的结构模板、场景卡、伏笔、对话、节奏怎么用。
> 本技能的核心不是「再写一套提示词」，而是**状态先行 + 机器可判 + 反 AI 腔门禁**；所有技法都必须能落回 `logic-rules.md` 的规则或 `story-state-schema.md` 的字段，否则只是口号。

## 3. 本技能的取舍与差异

**刻意做的事**

1. **确定性引擎优先**：能用机器判的（时间、空间、道具、知识、称谓、伏笔、字数、元信息）绝不交给 LLM 复述；LLM 只负责语义层（意图、动机、声音、潜台词）。
2. **门禁即事实**：任何「已通过」必须附命令 + 原始输出 + 规则 id；不允许「我觉得改好了」。
3. **反 AI 腔是阻塞级**：有评分、有词表、有人类负控、有三步调参出口；不是可选提示。
4. **状态先行**：frontmatter 是真源，账本只是断言；改设定必须三处同步。
5. **零依赖可移植**：纯 Node ESM，装完插件在用户自己的小说目录里可跑；脚本不可用时显式降级并留痕，不假装通过。

**刻意不做的事**

1. **不复刻「一键生成整本小说」**：本技能是创作工坊 + 质量门禁，不是自动写手；一章一交付。
2. **不做 RAG / 向量库 / 知识图谱**：状态用可 diff 的文本表达即可，引入检索层会让「可复核」变难。
3. **不做出版链**（EPUB/ISBN/排版）：导出只做 `exports/manuscript.md` 合并稿。
4. **不做跨书系列连续性**（v1.1 再议）。
5. **不按 genre 预设规则严重度**：当前靠「标注由 Agent 填 + 反向抽取复核 + 三步调参」控制误报，规则 profile 分级登记 v1.1。

## 4. 结构模板

### 4.1 三幕（最通用）

| 幕 | 占比 | 功能 | 必须发生的事 | 常见失败 |
|---|---|---|---|---|
| 第一幕：建置 | 25% | 人物、世界、want vs need | 打破平衡的激励事件；主角被迫行动 | 世界观倾倒；主角被动 |
| 第二幕：对抗 | 50% | 升级、反转、中点转折 | 中点翻盘（假胜或假败）；至暗时刻 | 中段疲软；反派不升级 |
| 第三幕：解决 | 25% | 高潮与代价 | 主角用「need」解决「want」；代价可见 | 天降解围；反派降智 |

**与场景卡的映射**：每幕至少一个「不可逆节点」，落在场景卡的 `outcome` 字段里（不是摘要，是状态变化：谁失去了什么、谁知道了什么）。

### 4.2 英雄之旅（12 阶段，长篇用）

| # | 阶段 | 章节映射建议 | 论文级提示 |
|---|---|---|---|
| 1 | 平凡世界 | 第 1 章前 1/3 | 用日常细节建立「他原本的样子」 |
| 2 | 冒险召唤 | 第 1–2 章 | 召唤必须打乱计划，不是发个通知 |
| 3 | 拒绝召唤 | 第 2 章 | 拒绝的理由要真实（恐惧/责任/代价） |
| 4 | 遇见导师 | 第 2–3 章 | 导师给工具不给答案 |
| 5 | 跨越门槛 | 第 3 章 | 离开后再也回不去（状态变化要落账） |
| 6 | 试炼/盟友/敌人 | 第 4–8 章 | 每组试炼都要改变关系 |
| 7 | 接近深渊 | 中段 | 准备好最坏的局面 |
| 8 | 苦难 | 中点前后 | 失去导师/盟友/信念之一 |
| 9 | 奖赏 | 中点后 | 奖赏要带代价 |
| 10 | 归途 | 后段 | 追兵/余波不能省 |
| 11 | 复活 | 高潮 | 用「need」而非「want」取胜 |
| 12 | 带着灵药回归 | 结尾 | 变化可见（人物卡 status/goal 要更新） |

### 4.3 救猫咪 15 拍（商业类型片节奏）

| 拍 | 位置 | 功能 |
|---|---|---|
| 开场画面 | 1% | 主角现状的隐喻镜头 |
| 主题陈述 | 5% | 有人点出主题（通常是错的版本） |
| 铺垫 | 1–10% | 展示「缺失」 |
| 催化剂 | 10% | 打破日常 |
| 争论 | 10–20% | 主角的犹豫 |
| 进入第二幕 | 20% | 主动选择进入新世界 |
| B 故事 | 22% | 爱情/友情/副线（承担主题） |
| 游戏 | 20–50% | 兑现类型承诺 |
| 中点 | 50% | 假胜利/假失败，倒计时开始 |
| 坏人逼近 | 50–75% | 压力升级 |
| 一无所有 | 75% | 最大失去，旧方法失效 |
| 灵魂黑夜 | 75–80% | 蜷缩、反思、被 B 故事点醒 |
| 进入第三幕 | 80% | 新计划（用 `need`） |
| 结局 | 80–99% | 逐级解决 |
| 终场画面 | 99% | 与开场对照 |

> 模板是**诊断工具**不是填空表：写不出来时问「现在缺哪一拍」，比照抄更有用。所有模板都要落回场景卡的 `goal/conflict/outcome`——没有状态变化的「节拍」不算节拍。

### 4.4 场景-后续（Scene & Sequel，微观结构）

| 单元 | 组成 | 写法要点 | 常见错误 |
|---|---|---|---|
| 场景 | goal → conflict → disaster | 目标具体可判（拿到/问出/活下来）；冲突升级两次；结局是「是的，但是/不，而且」 | 场景无目标；冲突一次就结束；结局不改变状态 |
| 后续 | reaction → dilemma → decision | 反应先情绪后理性；两难必须真的两难；决定导向下一个 goal | 后续变总结；内心独白超过场景本身 |

**节奏口诀**：动作戏用「场景」连排（压缩后续）；文戏用「场景-后续」交替；章末停在新决定或新威胁上。

## 5. 场景卡写法

场景卡在 `outline/outline.json`，是断言层；与章节 frontmatter 的 `scenes[]` 对齐。

```json
{
  "id": "ch3-s1",
  "place": "warehouse-3f",
  "cast": ["lin-jin", "xu-an"],
  "goal": "逼问怀表下落",
  "conflict": "徐岸撒谎",
  "outcome": "林烬夺走怀表，徐岸逃走",
  "hooks_plant": ["h2"],
  "hooks_pay": ["h1"]
}
```

| 字段 | 写对的标准 | 反例 |
|---|---|---|
| `goal` | 一句话、可判成败、属于某个具体人物 | 「推进剧情」「展现性格」 |
| `conflict` | 对立意志/障碍，不是「气氛紧张」 | 「两人都不说话」 |
| `outcome` | **状态变化**：谁得到/失去/知道/受伤/去了哪 | 「气氛更紧张了」 |
| `cast` | 本场真正有戏的人（不是「可能在」的人） | 把全城人都列上 |
| `place` | 已注册地点 id；异地连场要能走通 | 写「某个仓库」 |
| `hooks_*` | 已注册伏笔 id；埋/收必须成对出现在正文 | 卡里有、正文没有 |

**场景卡五问（写完自查）**：① 谁想要什么？② 谁/什么挡着？③ 结尾状态和开头比变了什么？④ 这一场删掉，后面哪里会塌？⑤ 这场让哪个伏笔前进了一步？

## 6. 伏笔生命周期

```
注册（hooks.jsonl：问题 + 断言 plant）
  → 埋设（章节 frontmatter hooks_plant，真源）
  → 提醒（可选：中间章节复现线索，不消耗 status）
  → 回收（hooks_pay；派生 status=PAID）
  → 作废（显式 status=BROKEN/DEFERRED；不得再有 hooks_pay）
```

| 状态 | 含义 | 允许动作 | 对应规则 |
|---|---|---|---|
| OPEN | 已埋未收 | 提醒、回收、转 DEFERRED | 超期（`当前最大章 - plant > staleAfter`）报 MAJOR |
| PAID | 已回收 | 不得再回收/再埋设同 id | 回收章早于埋设章 → BLOCKER |
| BROKEN | 设定作废 | 正文不得再回收 | 作废仍回收 → MAJOR |
| DEFERRED | 明示延后 | 写清延到哪卷 | 同 BROKEN 的回收检查 |

**三条纪律**

1. **断言从属于真源**：`hooks.jsonl` 写 `pay: 3`，正文写到第 5 章才收 → 报告提示改断言（不覆盖 frontmatter）。
2. **三处同步**：改伏笔设定时 `hooks.jsonl` + `outline.json` 场景卡 + 受影响章节 frontmatter 同批改；只改一处必红。
3. **超期是逼决策，不是催更**：超期后只有两个合法动作——排期回收，或显式 DEFERRED。第三条「假装忘了」会被下次 lint 抓住。

**判例**：某伏笔第 1 章埋，第 4 章正文里出现一句「那天的雨声又响起来」——这是**提醒**，不写 `hooks_pay`；第 7 章才真回收。若第 4 章误写进 `hooks_pay`，派生状态提前 PAID，第 7 章再回收就会命中「回收章早于埋设章/已回收再回收」类矛盾。

## 7. 对话写作要点

1. **潜台词优先**：关键对白里，人物说的≠想的。审校 rubric 4 会查「是否至少一半关键对白有潜台词」。
2. **信息不对称**：谁不知道什么、谁在套话，写进场景目标的冲突里；知识边界（`uses`）保证角色不说漏自己不知道的事。
3. **称谓即关系**：`appellations` 白名单不是形式主义——叫「林队」还是「阿烬」，是关系状态的显式表达；越界称谓会被规则抓。
4. **标签多样化**：少用「说道/问道/笑道」堆叠；用动作节拍（他把烟按灭）、停顿、视角切换替代。标签 top 占比过高会触发声音维提示。
5. **每句台词有功能**：推进信息 / 暴露人物 / 制造压力 / 埋伏笔。四者皆无的台词删。
6. **短句承压**：冲突升级时句子变短、提问变具体（「沙发朝哪边」比「你仔细想想」有压迫感）。
7. **方言/口癖克制**：口癖是人物标签，一段最多两次；过量读起来像模仿。
8. **对白不解释设定**：设定信息靠行动与世界细节漏出；「如你所知」式科普会被语义层判死。

## 8. 长篇节奏档位

### 8.1 章型配额（计划期使用，非硬性规则）

| 档位 | 章型 | 功能 | 建议配额 | 备注 |
|---|---|---|---|---|
| A | 推进章 | 状态不可逆变化（死/失去/知道/决裂） | 每 5 章 ≥2 | 缺 A 章 = 读者觉得「水」 |
| B | 升级章 | 冲突升级、代价加重、关系变化 | 每 5 章 ≥2 | 与 A 章交替 |
| C | 呼吸章 | 关系修复、日常、信息整理 | 每 5 章 ≤1 | 连续 2 个 C 章 = 掉追读 |

**反向刹车**：连续 2 个 A 章后必须给 C 章喘息（读者疲劳）；连续 2 个 C 章后必须给 A/B（弃书风险）。这个配额写进大纲计划（`outline.json` 的章级备注），不写成引擎规则——机械执行会伤创作。

### 8.2 卷级节拍

| 位置 | 节拍 | 检查问题 |
|---|---|---|
| 卷首 | 新目标 + 旧问题未解 | 读者知道本卷要什么吗？ |
| 20% | 第一次升级/反转 | 主角的旧方法失效了吗？ |
| 50% | 中点翻盘 | 代价可见吗？倒计时开始了吗？ |
| 75% | 最大失去 | 失去的是读者在意的东西吗？ |
| 95% | 高潮 | 用的是 `need` 而不是 `want` 吗？ |
| 卷末 | 新问题抛出 | 下一卷的钩子挂上了吗？ |

### 8.3 单章节拍（章末必须挂）

- 章末停在：新决定、新威胁、新信息、或关系破裂——**四选一**，不要停在总结。
- 章首 300 字内必须出现目标或冲突（读者耐心窗口）。
- 每章至少一个场景的 `outcome` 是状态变化；纯粹「过场」的场景合并进相邻章。

## 9. 上下文预算与写作闭环

**写前上下文 ≤5 文件**（`context` 命令产出）：大纲卡 + 上一章摘要 + castCards（大纲 cast ∪ 上章 cast，去重排序）+ 开放伏笔 + **全量索引**（facts/places **全量返回**，Agent 按本章 needs 自行裁剪；按需过滤登记 v1.1）+ 文风指南。**不喂**整本正文、不喂历史报告。

**每 10 章压缩一次摘要**：`summaries.md` 保持每章 1–3 句；卷末再压成 1 段卷摘要，防止上下文膨胀。

**写章闭环（每章一遍）**：

1. `context` 取料（只读，不改状态）；
2. 草稿正文 + 同步填 frontmatter 标注（Agent 填，不是用户填表）；
3. 六维逻辑闸：`lint`（退出码 0/1）；
4. 反 AI 腔：`prose` 或 `lint` 的 `aiVoice` 评分 → 定点改写 → 重扫；
5. 修复：按 `fixRoute` 改对应层（prose/bible/outline/config）；
6. 落账：frontmatter 与账本/大纲一致；
7. 门禁：`lint` 全绿（BLOCKER=MAJOR=0，strict 时 MINOR=0）才进下一章；
8. 摘要：写进 `summaries.md`；
9. 每 5 章：反向抽取复核（独立上下文反抽场景元信息对比 frontmatter）。

## 10. 与其它三份手册的接口

| 要查什么 | 去哪份 |
