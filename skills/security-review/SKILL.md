# Security Review（安全审查，只读）

## 定位

对改动或既有面做只读安全审查。DSH 环境的审查面与通用审查不同：除了代码本身，还要审插件/技能/配置/依赖/网络与权限边界。本技能不修改任何文件；发现只报告 + 建议修复路径（修复走 executor/ralph 等执行通道）。

## 审查清单（按此顺序）

1. **密钥与敏感数据**：
   - 仓库内的明文密码/令牌/私钥/连接串（包括历史提交与未跟踪文件）；
   - 日志/错误信息/测试夹具中的敏感值；密钥写进配置而非环境变量/密钥库。
2. **依赖与供应链**：
   - 已知 CVE 的依赖（后端看 trivy/SBOM 报告；前端看 npm audit / pnpm audit）；
   - 可疑新增依赖：无 star/无人维护/安装脚本（postinstall）执行任意代码；
   - 锁文件与清单不一致。
3. **注入与输入面**：
   - SQL 注入（字符串拼接、动态 order by）、命令注入（拼接 shell）、模板注入、路径穿越（用户输入拼文件路径）；
   - 反序列化不可信数据；XXE；正则 ReDoS。
4. **认证与权限**：
   - 弱/缺失认证、令牌泄漏面（URL/日志）、越权（缺少 owner 校验）、默认口令；
   - 密码策略与哈希算法（明文/弱哈希）。
5. **配置与部署**：
   - 危险默认配置（调试模式、宽松 CORS、开放端口）；
   - 部署脚本的密钥注入方式（明文环境变量进仓库）；
   - 换行/编码类部署事故（如 CRLF 脚本在 Linux 失效）与文件权限。
6. **DSH 插件/技能面（适用时）**：
   - 插件声明权限超出实际需要（filesystem:write 滥用）；
   - 技能/提示词注入面：技能正文引用外部文件、执行任意命令；
   - cordis 组合行是否只使用公开服务、副作用是否可回收（Fiber 拆除）。
7. **网络面**：
   - SSRF（用户可控 URL 被服务端请求）；不安全的 TLS 校验绕过；
   - 外部生产副作用是否经授权。

## 严重度与修复门槛

- **CRITICAL**：可利用漏洞或密钥泄露——立即报告，阻止合入/部署；
- **HIGH**：高危配置或明显风险面——合入前必修；
- **MEDIUM**：风险项——排期修复；
- **LOW**：加固建议。

每条发现给：位置（file:line 或配置项）、风险、利用场景、修复路径（具体到改哪）。

## 验证面（只读）

- 前端：npm audit / pnpm audit 输出、构建产物中的密钥串扫描；
- 后端：trivy/SBOM 报告、依赖树、配置明文扫描（grep 常见密钥名）；
- 通用：git log 历史扫描（曾提交过的明文密钥即使已删也建议轮换）、git status 未跟踪文件。

## 输出契约

```
## Security Review Report

Scope: <范围>
Findings: N（CRITICAL x / HIGH y / MEDIUM z / LOW w）

CRITICAL
- <位置> — <风险> — <利用场景> — <修复路径>

HIGH / MEDIUM / LOW
- ...

## Verified Surfaces
- <跑过的只读检查与结果>

## Verdict
- 可安全合入 / 修复 CRITICAL+HIGH 后可合入 / 阻止合入
```

## 最终清单

- [ ] 七个审查面都过了一遍（不适用项显式标注 N/A）
- [ ] 每条发现带位置 + 风险 + 修复路径
- [ ] 只读验证命令真实跑过（审计/扫描/密钥搜索）
- [ ] 历史明文密钥类发现附「轮换建议」
- [ ] 结论明确（可合入 / 有条件 / 阻止）
