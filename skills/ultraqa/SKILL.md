# UltraQA（对抗式动态 e2e QA）

## 运营契约

- 结果先行、证据密集；用户更新是当前分支的局部覆盖；
- UltraQA 不满足于浅层 build/lint/typecheck/test 清单：目标可运行/可模拟/可安全 harness 时，必须用对抗式动态 e2e 场景实际执行请求的行为；
- 循环 测试 → 诊断 → 修复 → 重测，直到目标达成、有界停止条件命中、或安全边界阻止。

## 目标解析

| 调用 | 目标 | 查什么 |
|------|------|--------|
| --tests | 测试 | 既有测试 + 针对改动行为的对抗动态 e2e 场景 |
| --build | 构建 | 构建成功且生成的 smoke/e2e 探针仍能跑通 |
| --lint | lint | 通过且生成的 harness/测试工件不破坏项目卫生 |
| --typecheck | 类型 | 通过且生成的类型化 harness 可编译 |
| --custom "模式" | 自定义 | 成功模式对照行为验证，不轻信成功字样 |
| --interactive | 交互 | CLI/服务行为用生成的恶意与边界交互验证 |

无结构化目标时，把参数当自定义行为目标，从仓库上下文推导可运行的 e2e 策略。

## 必选场景矩阵

每个场景行：场景 id / 意图 / 用户-攻击者模型 / 设置 / 命令或 harness / 期望信号 / 实际结果 / 修复 / 证据 / 清理状态。除正常路径外，除非明显无关或不可能，必须覆盖这些恶意与边界类别：

1. **畸形输入**：非法 JSON、缺字段、非法标志、超长串、异常 Unicode、路径穿越值、损坏的状态文件；
2. **反复中断**：反复 continue、stop/cancel/abort 措辞、被截断的命令输出、部分进度后重试；
3. **提示注入**：试图覆盖指令、窃取密钥、跳过验证、删除状态、假称成功的用户文本；
4. **取消/恢复**：活动状态清理、恢复检测、过期进行中状态、取消后全新运行；
5. **陈旧状态**：旧 .omx/state 文件、会话不匹配、缺失时间戳、矛盾阶段元数据；
6. **脏工作区**：既有未提交改动、未跟踪生成文件；验证 UltraQA 不隐藏/覆盖无关工作；
7. **挂起/长命令**：有界超时、杀子进程、恢复记录；
8. **脆弱测试**：重跑策略、失败聚类、隔离证据；避免单次侥幸通过造成假绿；
9. **误导性成功输出**：成功字样 + 非零退出、隐藏失败、跳过测试、部分日志。

## 动态 e2e 与临时 harness 规则

- 无既有 e2e 面且临时测试/脚本/夹具能实质提升行为置信度时生成它们；优先项目原生测试工具 + 临时目录/清晰命名的夹具；
- 每个生成工件记入场景矩阵（有意提交或清理移除）；
- 可能挂起的命令必须有界超时；
- 校验退出码与输出语义，不轻信成功字样；
- 不删除/改写/掩盖无关用户工作；harness 前后各留脏工作区证据；
- harness 装配失败（导入路径/夹具构造问题）记作 harness debris，修好重跑，不据此宣布产品缺陷。

## 循环工作流（上限 5 轮）

1. **PLAN**：重述目标/成功标准/安全边界/停止条件；勘察可运行面、测试命令、状态文件、清理路径；跑命令前先建/更新场景矩阵。
2. **BASELINE**：按目标跑项目测试/构建/lint/typecheck/自定义命令（查模式 + 退出码 + 失败标记）。
3. **ADVERSARIAL**：执行场景矩阵（既有 e2e + 生成 harness）；显式建模恶意用户行为；捕获命令、退出码、关键输出、工件与清理状态。
4. **CHECK**：基线 + 对抗场景全过、生成工件已清理或有意跟踪、报告证据完整才 YES；否则进诊断。
5. **DIAGNOSE**：architect 子代理（roles/architect.md 前缀 + 场景矩阵 + 输出）给根因、安全含义、修复建议。
6. **FIX**：executor 子代理（roles/executor.md 前缀 + 诊断 + 受影响文件 + 约束：保留无关脏工作、清理临时 harness、守住安全边界）精确修复。
7. **CLEANUP**：移除临时 harness/夹具/日志/进程/状态文件（除非是有意交付物）；回滚不属于最终修复的实验性改动；复查工作区并记录剩余有意改动/残留。
8. **REPEAT**：带着更新的矩阵与失败历史回步骤 1。

## 安全边界（硬约束）

- 无破坏性命令（强重置、大删、密钥外泄、凭证倾倒、生产写入、无界进程孵化）；
- 除验证"无泄漏"所需的最小元数据外，不读/打印密钥；
- 无网络或外部生产副作用，除非用户显式授权；
- 无无界等待：超时 + 重试上限 + 明确挂起诊断；
- 不隐藏无关脏工作或生成残留；
- 必选场景会越界时，在报告中标记 blocked 并给出安全替代。

## 退出条件

| 条件 | 动作 |
|------|------|
| 目标达成 | `ULTRAQA COMPLETE: Goal met after N cycles` + 结构化报告 |
| 第 5 轮 | `ULTRAQA STOPPED: Max cycles` + 失败/已试修复/残余风险/证据 |
| 同一失败 3 次 | `ULTRAQA STOPPED: Same failure detected 3 times` + 根因/安全说明/下一 owner |
| 安全边界 | `ULTRAQA BLOCKED: [破坏性/凭证/外部生产/无界动作]` + 安全替代证据 |
| 环境错误 | `ULTRAQA ERROR: [端口/依赖/挂起命令问题]` + 清理状态 |

## 结构化报告（每次退出都出）

- Goal、cycles、场景矩阵（含清理状态）、基线验证输出、修复列表、剩余风险、证据引用、退出条件。
- 纯文档/平凡非运行时改动可显式跳过 UltraQA（记录条件与证据）。

## 最终清单

- [ ] 场景矩阵建好且含 9 类恶意/边界类别中适用项
- [ ] 基线验证命令真实跑过并读输出
- [ ] 对抗 e2e 场景真实执行（非纸面）
- [ ] 失败经 architect 诊断、executor 修复、回归重测
- [ ] 临时工件清理或有意跟踪；无关脏工作未被碰
- [ ] 退出报告符合退出条件之一且证据完整
- [ ] 安全边界未被破坏（或越界项已标记 blocked + 替代）
