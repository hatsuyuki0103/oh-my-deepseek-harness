# Visual Ralph（视觉对齐编排）

> 可选能力：本技能引用的可选工具（DSH 原生 `ralph` 工具、官方团队九工具、`workflow`、`subagent`/`subagent_fork`）可能在当前 profile 未挂载或被预设停用；探测方式与四级降级阶梯见本包根目录 `docs/capability-matrix.md`（技能目录上两级：`../../docs/capability-matrix.md`）。

## 目的

按一份已批准的视觉参考，把 UI 实现/重构到与参考一致，并留下可复用的设计系统。核心循环：

`参考图/URL 基线 -> 用户批准闸 -> ralph 实现 -> 每次编辑前视觉裁决（read_image 判分）-> 像素差热图（可选次级证据）-> 可复用设计系统`

参考仓库 oh-my-codex 的 visual-ralph（含并入的 web-clone 用例）移植到 DSH 原生机制：没有 OMX 的 imagegen / 内部 vision 工具 / notify-hook，视觉判定由**会话视觉模型 + DSH `read_image` 工具**完成，OMX 风格的 ralph 点调用换成 DSH 双引擎（原生 `ralph` 工具 / 会话内 ralph 纪律，见 ralph 技能）。

## 何时使用 / 何时不用

使用：

- 用户要按视觉目标（静态参考图、设计稿截图、或仓库已有截图脚本能抓的 URL 基线）实现/重构 Web/前端 UI；
- 需要像素级迭代，且结果必须留下仓库原生的 tokens/组件，而不只是一张"看起来像"的截图；
- 用户明确说"照着这个图做 / 视觉对齐 / 按参考实现"。

不用：

- 只要设计简报（DESIGN.md，用 design 技能）；
- 纯后端/API/非视觉工作（直接做）；
- 已有实现只需对照修问题——可直接走 ralph，不必带视觉裁决；
- 确定性 SVG / 代码原生资产（不需要视觉裁决）。

## 前置能力与边界

- **视觉判定**：本会话模型支持图像输入；用 DSH `read_image` 工具读取截图/参考图后进行结构化判分。**会话模型不支持图像输入时，不进入本技能**：报告用户并转人工视觉确认。
- **参考图来源**：DSH 无内置浏览器截图与图像生成工具。参考图 = 用户提供的图片文件，或仓库已有截图脚本（如 playwright 脚本）产出的基线截图。URL 基线必须记录：来源 URL、视口、路由/状态、登录/种子假设、排除项（后端/API/鉴权、个性化数据、第三方组件、爬取限制）。
- **像素差**：可选次级证据。环境存在 pixelmatch/pngjs（node）时可用热图定位差异热点；不存在时以视觉判分为准，不安装新依赖。

## 工作流

### 1. 接地仓库

读仓库证据：包管理器与脚本、前端框架与路由、样式/token 约定、已有的截图工具与可复用组件。只在仓库证据支持时才给出栈相关命令。

### 2. 建立参考

- **静态图**：把批准用的参考图副本放到 `.omx/artifacts/visual-ralph/<slug>/reference.png`（.omx 工作区约定；artifacts 为本技能自约目录），不要只留在浏览器或临时目录。
- **URL 基线**：记录来源 URL 与权限/范围、视口、路由/状态、种子与登录假设、截图命令或已保存截图路径、可见控件对照说明与排除项（后端/API/鉴权、个性化数据、第三方部件、爬取限制）。
- 生成型概念：DSH 无图像生成工具——由用户提供生成图或现有 mockup 文件，按上述参考图路径落盘。

### 3. 批准闸

生成/抓取后停下，**先征求用户批准一张参考图/基线状态**（或按用户反馈定向再抓/再选）。批准前不得开始实现、不得调 ralph。批准后该图/基线为视觉唯一事实源；重大方向转变必须由用户显式要求。

### 4. 移交 ralph

把下面交接模板 + 用户任务描述交给 ralph（DSH 原生 ralph 工具轮次，或会话内 ralph 纪律；遵循 ralph 技能的 goal 集成与完成审计）。

### 5. 每次编辑前裁决（核心）

每次迭代：按截图命令/视口抓当前状态 → `read_image` 打开截图 → 按**视觉裁决 JSON** 判分，并把该 JSON 当作本轮权威结论：

```json
{
  "score": 85,
  "verdict": "需要修改",
  "category_match": "布局层级基本一致，配色与间距偏差明显",
  "differences": [
    "主色与参考图不符：参考为深蓝 #1E3A5F，当前为 #3A5F7F",
    "卡片圆角偏大：参考 8px，当前 16px",
    "标题字重不足：参考 600，当前 400"
  ],
  "suggestions": [
    "将主色变量改为 #1E3A5F 并核对明暗态",
    "卡片圆角降至 8px",
    "标题字重提升到 600"
  ],
  "reasoning": "逐项对照了配色、圆角与字重；总体同构，无布局级偏差，达到 90 前需先修这三项"
}
```

- 必需键：`score`、`verdict`、`category_match`、`differences[]`、`suggestions[]`、`reasoning`，共 6 键。
- `score < 90`：把 `differences[]` 与 `suggestions[]` 转成下一轮编辑计划，**先改再截再判**，不允许未经判分直接编辑；`score >= 90` 才算通过。
- 判定短视/漏项时（明显差异未入列），以人工复核为准并重新判分。

### 6. 次级像素差证据

像素差/pixelmatch 热图只用于**定位热点**并转成编辑；热图不替代视觉判分。最终产物记录：参考图、每轮截图、差异热图（存 `.omx/artifacts/visual-ralph/<slug>/`）以便审计。

### 7. 可复用设计系统

把匹配结果编码进仓库既有 CSS 变量/主题 token/组件变体/story/DESIGN.md：覆盖颜色、间距、字体与字重、圆角、阴影与层级、重要变体与状态。**扩展既有模式，不新增平行层**。

## 完成证据与停止条件

满足以下才算完成：已保存批准参考/基线与可复现命令（视口、路由、状态、输出路径）；最终裁决 `score >= 90`；次级差证据已记录（或明确说明未用像素差的原因）；可复用 tokens/组件已落地；仓库等价构建/lint/测试验证通过；未发生未批准的转向；剩余差异已记录。停在批准闸，或证据无法满足时报告具体阻塞。
